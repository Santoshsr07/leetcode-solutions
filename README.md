## 🧠 How I Approach a Problem

```text
┌─────────────────────┐
│  1. Understand      │  ← Constraints, examples, edge cases
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  2. Find the Pattern│  ← DS / algorithm / reusable idea
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  3. Build a Solution│  ← Correctness first
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  4. Analyze         │  ← Time + space complexity
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  5. Optimize        │  ← Remove unnecessary work
└──────────┬──────────┘
           ↓
┌─────────────────────┐
│  6. Revisit         │  ← Turn solutions into patterns
└─────────────────────┘
```

### ⚡ Complexity First

| Complexity | Typical Pattern |
|:---:|:---|
| `O(1)` | Direct access / constant operations |
| `O(log n)` | Binary search / divide & conquer |
| `O(n)` | Two pointers / hashing / sliding window |
| `O(n log n)` | Sorting / efficient divide & conquer |
| `O(n²)` | Nested traversal when constraints allow |

> An **Accepted** submission is the checkpoint, not the finish line.
