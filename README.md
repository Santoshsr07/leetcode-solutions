## 🧠 Problem-Solving Approach

For each problem, I try to focus on more than just getting an accepted submission:

1. Understand the problem and constraints.
2. Identify the underlying pattern or data structure.
3. Build a correct solution.
4. Analyze **time and space complexity**.
5. Look for opportunities to reduce unnecessary work.
6. Keep the solution organized by topic for future revision.

Some solutions also include the original problem statement and examples alongside the implementation, making the repository useful as a personal revision archive.

## ⚡ Complexity Matters

I don't consider an accepted solution the end of the problem. An important part of this repository is comparing approaches and looking for better complexity.

Typical complexity targets include:

- **O(1)** — constant-time operations where possible
- **O(log n)** — binary search and divide-and-conquer techniques
- **O(n)** — linear scans, hashing, two pointers, and sliding windows
- **O(n log n)** — sorting and related approaches

When a problem has a significantly better approach than my first solution, it becomes an opportunity to improve rather than simply move on.
